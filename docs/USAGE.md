## 1. 安装与启动

只能在 **Windows 10 / 11** 上运行（输入注入走 Win32，无法跨平台）。

### 源码方式

```powershell
pip install -r requirements.txt   # 依赖只有 PySide6
python main.py
```

### 打包成 exe（给别人用 / 免装 Python）

```powershell
pip install pyinstaller
build.bat            # 会先跑四套测试，任何一套不过就不打包
```

产物 `dist\AutoClicker.exe`，单文件、无控制台窗口，双击即用。
（放一个 `AutoClicker.ico` 在项目根目录，`build.bat` 会自动带上它。）

### 首次启动

会在 `%LOCALAPPDATA%\AutoClicker\` 下建好 `settings.json`、`profiles\`、`shots\`、`logs\`。
程序是**单实例**的，重复启动会唤起已有窗口。

## 3. 五分钟上手

1. 点 **`+ 点击`**，在弹窗里设置参数（或先点「拾取坐标 (F8)」定坐标）。
2. **取坐标**：对话框里点「拾取坐标 (F8)」，屏幕压暗后把鼠标移到目标位置、**左键**确认；
   对话框会先自动隐藏、拾取完再弹回来。也可以关掉对话框，在主窗口**选中某一行**后按 **F8**
   改写它的坐标。
3. 继续加 **`+ 延时`**（等界面加载）、**`+ 按键`**（例如 F5 刷新）。
4. 临时不想跑某一步：取消该行 `启用` 列的勾。
5. 设 **序列轮数**（填 `0` = 无限，直到按 F10）与 **启动延迟**（留出切换窗口的时间）。
6. 按 **F9** 开始（勾了「开始后最小化窗口」会自动最小化），**F10** 停止。

> ⚠️ 默认是 `SendInput` **前台注入**：它会真实移动系统光标并产生真实点击，
> **运行期间不要动鼠标**。要一边跑一边用鼠标，见 [第 7 节 后台点击](#7-后台点击不占用鼠标)
> 或 [第 8 节 UIA 无障碍点击](#8-uia-无障碍点击不移动鼠标)。

## 4. 五种步骤

| 类型 | 主要字段 | 说明 |
|---|---|---|
| **点击** | 坐标 X/Y、按键、次数、间隔 ms、间隔抖动 ms、坐标抖动 px | 「次数 + 间隔」即连点；抖动用来避免被识别成机械点击 |
| **延时** | 延时 ms、抖动 ms | 等**固定时长**。等「不确定何时出现」的东西请用找图 |
| **按键** | 按键（下拉）、次数、间隔 ms | 发给**焦点窗口**，所以要先把目标窗口切到前台 |
| **移动** | 折线点（`拾取终点 (F8)`）、总时长 ms | 用来还原「划过去再点」这类悬停动作 |
| **找图** | 见 [第 6 节](#6-找图等某个东西出现) | 等屏幕上出现某张图片再继续 / 再点它 |

坐标拾取也可以在对话框里进行：点「拾取坐标 (F8)」，或对移动步骤点「拾取终点 (F8)」。

## 5. 录制回放

不用手搭步骤，直接录一遍：

1. 点「录制 (F11)」或按 **F11**，主窗口让开，屏幕顶部出现「● 录制中」指示条。
2. 正常操作鼠标键盘。指示条实时显示录到的点击/按键数与移动采样数。
3. 按 **F10** 结束，弹窗选择 **替换当前步骤 / 追加到末尾 / 丢弃**。
4. 内容进步骤表后可直接编辑、调时长、调顺序，再按 F9 回放。

录制会自动做三件「整理」，结果通常比想象中干净：

- **连点合并**：同一个点连点 5 下 → 一个「点击 ×5，间隔 150ms」，而不是 5 行；
- **连按合并**：同一个键重复按 → 一个「按键 ×N」；
- **轨迹压缩**：一整段鼠标移动 → **一个**「移动」步骤（内部存折线拐点 + 总时长），
  默认抽稀到 12px / 80ms 一个点，2px 以内的手抖直接丢掉。

录完想微调坐标不用重录：选中那一行按 **F8**。点击步骤改的是落点坐标，
移动步骤改的是**终点**（起点保留、中间拐点拉直）。

### 两个录制开关

| 开关 | 默认 | 作用 |
|---|---|---|
| 记录鼠标移动 | 开 | 关掉后只录点击和按键，步骤更精简。开着才能还原「移到菜单上再点」这类悬停操作 |
| 屏蔽输入 | 关 | 勾上后录制期间鼠标键盘**不会传给任何程序**，纯空录坐标和节奏，绝不会误点。代价是「点开菜单 → 再点菜单项」这种有依赖的流程录不出来（菜单根本不会打开） |

> 勾了「屏蔽输入」时 **F10 是唯一的结束方式**，因此工具会先确认 F10 热键注册成功才允许开录，
> 避免把你锁在一个点不动的系统里。不勾选时 F10 依然最方便，托盘菜单也能结束。
>
> 录制期间不记录工具自己的控制键（F8/F9/F10/F11），也忽略其它程序注入的事件，
> 所以不会把回放动作又录一遍。

## 6. 找图：等某个东西出现

录制只能记下「什么时候做了什么」，记不下「等某个按钮出现再点」；找图步骤来补这一环。

1. 点 **`+ 找图`**，对话框里点「**截取屏幕**」。
2. 屏幕压暗后**左键拖一个框**框住要认的目标（比如「继续」按钮），松手即完成截取。
   框太小会被当成误触，直接重拖即可；右键或 Esc 取消。
3. 回到对话框，上方显示模板预览、尺寸，并提示这块画面「含多少像素的纯色区域」。
   出现**橙色警告**说明这块没有纯色底色、匹配会更脆，**建议把按钮的底色一起框进来**。
4. 调参数（一般默认值就够）：

   | 字段 | 说明 |
   |---|---|
   | 容差 | 抽样比对时每通道允许的色差，默认 32。主要用于容忍文字抗锯齿 |
   | 超时 | 最多等多久，默认 30 秒。填 `0` 表示只找一次，找不到立刻按「超时后」处理 |
   | 轮询间隔 | 每隔多久看屏幕一眼，默认 300ms。每看一眼都要抓一帧整屏，间隔越大越省 CPU |
   | 找到后点击它 | 勾上就点一下模板中心（可加偏移、可换按键）；不勾就只「等它出现」 |
   | 超时后 | 「继续下一步」或「停止并报错」 |

5. 点「**模拟测试**」可以不跑宏、不点鼠标，就地抓一帧看看现在能不能找到——调容差时非常省事。
   （测试时对话框会先自动隐藏，否则会先命中对话框里的模板预览图。）

> 找不到时会提示「是颜色完全没对上」还是「有几处颜色接近但形状不对」：
> 前者基本是目标没显示或界面变了，后者才值得调容差。

## 7. 后台点击（不占用鼠标）

默认点击走 `SendInput`，是**前台注入**：真实移动系统光标，所以运行期间不能动鼠标，
目标窗口也必须在前台。把主窗口「**输入方式**」下拉框换成「**后台点击（PostMessage，不占鼠标）**」后改用它：

- 点击变成**往目标窗口的消息队列投递** `WM_MOUSEMOVE` / `WM_LBUTTONDOWN` / `WM_LBUTTONUP`；
- **不移动系统光标**，宏跑着的时候你照样能用鼠标；
- **不要求目标窗口在前台**，部分被遮挡也能点（前提是拿得到它的窗口句柄 HWND）。

后台点击需要一个**目标窗口**，用于把屏幕坐标换算成该窗口的**客户区坐标**。两种给法：

1. **绑定窗口（推荐）**：点「**绑定窗口**」，屏幕压暗后点一下目标窗口即可。
   之后所有点击都投给它——哪怕它被别的窗口挡在前面。
2. **不绑定**：每次点击时找该屏幕坐标处**当时最顶层**的窗口来投递。省事，但目标被盖住时会投错。

> ⚠️ **后台点击适用面比前台窄**，这是 `PostMessage` 机制的固有局限，不是 bug：
>
> - 只对**自己处理鼠标消息**的经典 Win32 窗口有效。Chromium/Electron（大部分新版应用与
>   浏览器）、DirectX 游戏、不少 UWP 会**直接忽略**投递进来的消息，表现为「点了没反应」；
> - 不会产生 `WM_ACTIVATE` / 焦点变化，个别控件要先获得焦点才响应；
> - **发送方与目标进程的权限级别要匹配**：Windows 的 UIPI 会拦掉低权限进程发往高权限进程的
>   消息（例如本工具没提权、目标是管理员程序），表现为投递失败或没反应；
> - **键盘消息**只能投给绑定窗口（没绑定就退而求其次给前台窗口），后台键盘比后台鼠标更不可靠；
> - 换台机器、目标程序重开过之后 HWND 会失效，届时会**自动退回**按坐标识别窗口兜底。
>
> 一句话：**能前台就用前台**；只有当「不能占用鼠标 / 目标窗口拿不到前台」时，才值得赌一把后台，
> 且优先手动绑定窗口。

**点了没反应怎么办？** 那多半是目标程序不认 `WM_*`（网页控件就是这样）。下一步试
[第 8 节 UIA 无障碍点击](#8-uia-无障碍点击不移动鼠标)，或者直接跑一次探针让它替你判断：

```powershell
python tools\probe_background.py
```

它会自己给结论（前台 / 后台 / UIA 里选一条 + 置信度 + 理由），并**实测**给你看哪条真的生效。

## 8. UIA 无障碍点击（不移动鼠标）

`PostMessage` 对**网页控件**（Chromium / Electron / JCEF，以及 IDEA 里内嵌的网页）一定走不通——
消息投进去会被渲染器丢掉，表现为「点了没反应」。这类界面还有一条「中路」：**UI Automation**。

UIA 不看像素、也不投消息，而是**按控件办事**：拿坐标问系统「这里是哪个控件」，再让那个控件
执行它自己的「被点击」语义（`InvokePattern.Invoke()`）。

- **不移动系统光标**，宏跑着的时候你照样能用鼠标；
- **不抢焦点**，目标窗口不必在前台，被挡在后面也行；
- 找图依然负责**「在哪儿」**（像素定位），UIA 只负责**「怎么按下去」**——两者搭配使用。

怎么选：把主窗口的「**输入方式**」下拉框换成「**UIA 无障碍（按控件点击，不移动鼠标）**」。
「**绑定窗口**」按钮在 UIA 模式下含义变了——它不再是「往哪儿投消息」，而是**安全校验**：

> `ElementFromPoint` 按**屏幕坐标**取控件，如果目标被别的窗口**挡在下面**，取到的会是**遮挡它的
> 那个窗口的控件**。绑定窗口之后，取到的控件凡是不属于绑定的进程，就**跳过这一跳并在日志里
> 告警**——宁可漏点一次，也不要误点别人。没绑定时不做这层校验。

> ⚠️ **UIA 的适用面同样是有限的**，这是无障碍树的固有约束，不是 bug：
>
> - 目标程序**必须暴露无障碍树**。Swing/AWT 程序（含 IDEA）要开 Java Access Bridge
>   （命令行 `jabswitch -enable`）**并且**开 IDEA 的
>   `Settings → Appearance & Behavior → Appearance → Support screen readers`，**改完要重启 IDEA**。
>   Chromium/Electron 多数情况下默认就有。
> - **只有「有 Invoke 语义」的控件能点**：按钮、链接、菜单项、列表项可以；纯文本、空白区域不行。
>   取到的常是按钮**里面的文本节点**，所以程序会自动**往上找几层祖先**（默认最多 3 层），
>   找到第一个能 Invoke 的控件再点。
> - **右键 / 中键、移动鼠标、按键在 UIA 里没有对应语义**，这三种操作会**回落到前台注入**
>   （日志里会提示一次，每次运行重新提示）。也就是说：UIA 模式保证的是**左键点击不占鼠标**，
>   不是「整个宏绝对不碰鼠标」。
> - 目标以管理员运行时同样受 UIPI 限制（没提权就点不到）。
>
> 一句话：**能前台就前台；不能占用鼠标时，先探针——它会在「后台点击」和「UIA」之间给你答案。**

## 9. 热键与托盘

| 键 | 作用 |
|---|---|
| F9 | 开始回放 |
| F10 | 停止回放 / 结束录制 |
| F8 | 拾取坐标（编辑对话框开着时由对话框接管） |
| F11 | 开始录制 |

热键用 `RegisterHotKey` 注册，是**系统级独占**的。若提示注册失败，说明已被别的程序占用，
此时仍然可以用界面按钮或托盘菜单操作。

**点窗口的关闭按钮是最小化到托盘**，不是退出。托盘右键菜单：
`开始点击 (F9)`、`停止 (F10)`、`拾取坐标 (F8)`、`开始/结束录制 (F11)`、`退出`。
要真正退出，用托盘菜单的「退出」，或菜单栏「方案 → 退出」。

## 10. 方案文件

放在 `%LOCALAPPDATA%\AutoClicker\profiles\*.json`，是纯 JSON，可以直接手改、备份或分享。
找图模板**自带**在 JSON 里（`base64(magic + 宽高 + zlib 压缩的 BGRA)`），
所以方案文件换台机器也能直接用，不需要额外的图片文件。

```jsonc
{
  "version": 1,
  "name": "默认方案",
  "repeat": 0,                 // 整个序列重复轮数，0 = 无限
  "repeat_delay_ms": 0,        // 每轮之间的间隔
  "start_delay_ms": 300,       // 按开始后的等待时间
  "steps": [
    { "kind": "click", "enabled": true, "x": 960, "y": 540, "button": "left",
      "repeat": 10, "interval_ms": 200, "jitter_ms": 0, "jitter_px": 0, "note": "" },
    { "kind": "delay", "enabled": true, "delay_ms": 1500, "jitter_ms": 200, "note": "等加载" },
    { "kind": "wait",  "enabled": true, "template": "QUNUMXgAeAD...", "tolerance": 32,
      "timeout_ms": 30000, "poll_interval_ms": 300, "click": true, "button": "left",
      "offset_x": 0, "offset_y": 0, "on_timeout": "continue", "note": "等「继续」弹窗" },
    { "kind": "move",  "enabled": true, "points": [[100, 200], [180, 205], [300, 260]],
      "duration_ms": 420, "note": "划过去再点" },
    { "kind": "key",   "enabled": true, "vk": 116, "repeat": 1, "interval_ms": 50, "note": "F5 刷新" }
  ]
}
```

写入采用「临时文件 + 原子替换」，中途崩溃不会留下半个文件；
单个步骤损坏只会被跳过并记日志，不会让整个方案打不开。

日志文件在 `%LOCALAPPDATA%\AutoClicker\logs\autoclicker.log`（滚动保留，最多 3 个备份）；
找图超时中止时的现场截图在 `shots\`（只留最近 10 张）。

## 11. 常见坑

1. **运行期间动鼠标** → 前台注入的点击会跟着光标跑偏。要么别动，要么改用后台点击 / UIA。
2. **目标程序以管理员运行** → UIPI 会静默丢掉你的点击。「点了没反应」先想这条，
   改成以管理员身份运行本工具。
3. **游戏 / DirectX / 部分 UWP 无效** → 它们绕过标准输入队列，本工具无解。
4. **纯按键步骤点空** → 按键发给焦点窗口，先把目标窗口切到前台（后台 / UIA 模式下的按键同样
   更不可靠，UIA 会直接回落到前台注入）。
5. **换主题 / 换语言 / 改 DPI 缩放后找图失效** → 找图是原尺寸逐像素精确匹配，
   必须重新截模板；「容差」救不回整体变色。
6. **找图在 4K 多屏上吃 CPU** → 它是全屏搜索，每帧抓整屏约 50ms，把「轮询间隔」调大些。
7. **找图找不到被挡住的窗口** → 被完全遮挡、最小化、翻到后台标签页都找不到（找图是抓屏比对，
   抓到的只是可见像素）。UIA 也一样：它按屏幕坐标取控件，目标被挡在下面时会取到遮挡者的控件
   ——绑定过窗口就会被那层校验拦下。本工具不做「不看屏幕、直接在控件树里搜按钮」的定位。
8. **UIA 模式点了没反应** → 先确认目标是**按钮/链接/菜单项**这类有 Invoke 语义的控件（纯文本
   和空白区域点不动），再确认它暴露了无障碍树：Swing/AWT 程序要开 Java Access Bridge
   （`jabswitch -enable`）**且**开「Support screen readers」，改完**重启目标程序**。
   判断方法还是跑一次 `python tools\probe_background.py`（见第 7 节末尾）。
9. **录制期间切不动别的窗口** → 「屏蔽输入」下所有鼠标键盘都被吃掉，这是设计如此，按 F10 结束即可。
